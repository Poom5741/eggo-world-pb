**Goal:** Polish wallet balance display with improved UX states
**Depends on:** None
**Plans:** 1 plan

Plans:

- [x] 57-01: Add skeleton card, smooth fade-in, refined error state, number formatting, and test coverage

**Details:**

- Loading: Skeleton card with 5 pulsing placeholder blocks (title, description, balance number, USD line, sync button) — early return pattern, no skeleton during background polls
- Animation: `animate-fade-in duration-500` with `requestAnimationFrame` trigger for smooth 500ms opacity transition

- Tests: 35 tests (53 expect calls), file-content-assertion + renderHook patterns
- Pre-existing bug (deferred): use-wallet-poll.ts infinite re-render on 5xx errors

## Milestone Summary

**Key Decisions:**

- Single (non-unified) wallet page — focused on balance polish only, deposit/withdraw pages stay separate
- `initialLoadComplete` pattern to distinguish initial fetch from background polling (prevents skeleton flash)
- Inline error state inside balance card rather than full-page error or separate error component
- `toLocaleString` for number formatting (consistent with locale conventions, replaces `toFixed(2)`)

**Issues Resolved:**

- Wallet balance lacked visual feedback during initial loading (blank flash)
- Error state was a separate Card below balance card (disconnected UX)
- Number formatting was inconsistent (USDT used `toFixed(2)`, USD used raw value)

**Issues Deferred:**

- use-wallet-poll.ts infinite re-render on 5xx errors (errorCount in useCallback deps causes cascade)
- Legacy UAT gaps from prior milestones (Phase 10, 15, 17, 22, 23, 26, 27, 28, 29, 30, 56)
- Legacy verification gaps (Phase 03, 12, 19, 20, 49)

**Technical Debt Incurred:**

- Pre-existing `use-wallet-poll.ts` re-render bug documented but not fixed
