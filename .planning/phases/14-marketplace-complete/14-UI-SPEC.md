## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage                     |
| ----- | ----- | ------------------------- |
| xs    | 4px   | Icon gaps, inline padding |
| sm    | 8px   | Compact element spacing   |
| md    | 16px  | Default element spacing   |
| lg    | 24px  | Section padding           |
| xl    | 32px  | Layout gaps               |
| 2xl   | 48px  | Major section breaks      |
| 3xl   | 64px  | Page-level spacing        |

**Exceptions:**

- BottomNavMobile height: `h-24` (96px total) — includes iOS safe area inset (`env(safe-area-inset-bottom)`)

- Claymorphism padding utilities: `p-clay-sm` (12px), `p-clay` (16px), `p-clay-md` (20px) — non-standard multiples for design system consistency

**Source:** `globals.css` lines 709-723 (claymorphism spacing utilities)

## Layout Contract

### Responsive Breakpoints

| Breakpoint | Width  | Target Device                       | Navigation                |
| ---------- | ------ | ----------------------------------- | ------------------------- |
| xs         | 320px  | Smallest mobile (iPhone SE)         | BottomNavMobile (4 items) |
| sm         | 375px  | Standard mobile (iPhone Mini/Pro)   | BottomNavMobile (4 items) |
| md         | 768px  | Tablet (iPad portrait)              | BottomNavMobile (4 items) |
| lg         | 1024px | Tablet landscape / Desktop boundary | SideNav (full)            |
| xl         | 1440px | Large desktop                       | SideNav (full)            |

**Mobile breakpoint:** `< 1024px` (Tailwind `lg:` prefix)
**Desktop breakpoint:** `≥ 1024px` (Tailwind `lg:` prefix)

### Layout Rules

1. **No horizontal scroll** at any breakpoint — use `overflow-x-hidden` on body, `max-width: 100%` on images
2. **Container width:** `max-w-7xl mx-auto px-4 sm:px-6 lg:px-8` (from existing globals.css)
3. **BottomNavMobile:** Fixed to bottom, `h-24` (96px), `rounded-t-[2.5rem]`, backdrop blur
4. **SideNav:** Hidden on mobile (`lg:hidden`), visible on desktop (`lg:flex`), `w-72`, `rounded-r-[3rem]`
5. **Safe area:** BottomNavMobile uses `paddingBottom: 'env(safe-area-inset-bottom)'` for iPhone notch
6. **Claymorphism shadows:** Reduced complexity on mobile (`@media (max-width: 768px)`) — see globals.css lines 743-753

### Touch Target Requirements

- **Minimum size:** 44×44px (WCAG 2.2)
- **BottomNavMobile items:** Each nav item must have `min-h-[44px]` and `min-w-[44px]`
- **Icon-only buttons:** Add invisible padding to reach 44px (e.g., `p-3` on 24px icon)
- **Links in SideNav:** `py-3` (~12px + text height) — verify total height ≥ 44px
- **Buttons:** Existing `btn-primary`, `btn-secondary` use `py-3 px-6` — verify height ≥ 44px

**Source:** REQUIREMENTS.md (QUAL-03 through QUAL-06), 14-SPEC.md, `globals.css` lines 743-753

## Components

### BottomNavMobile (Modified)

**Current state:** 6 navigation items (Dashboard, Eggs, Animals, Marketplace, Referrals)
**Target state:** 4 navigation items (Dashboard, Eggs, Animals, Marketplace)

**Changes required:**

1. Reduce `NAV_ITEMS` to 4 items for mobile display
2. Move Referrals to SideNav only (desktop) or secondary menu
3. Ensure each item has 44×44px touch target
4. Active tab highlighted with icon + color change (use `text-[var(--primary)]`)
5. Smooth fade-in animation on mobile breakpoint transition

**Implementation approach:**

- Create `MOBILE_NAV_ITEMS` constant (4 items) separate from `NAV_ITEMS` (5 items)
- Or filter `NAV_ITEMS` to exclude Referrals on mobile
- Use `useIsMobile()` hook from `@/components/ui/use-mobile.tsx` for conditional rendering

**Source:** `BottomNavMobile.tsx`, `SideNav.tsx` lines 11-17

### SideNav (Unchanged)

- Remains hidden on mobile (`lg:hidden`)
- Full navigation visible on desktop (5 items + Settings + Support)
- No changes required for this phase

### Input Fields (Modified)

**Current state:** `input-field` class uses `text-xs` (~14px) — triggers iOS zoom
**Target state:** All inputs use `text-base` (16px) minimum

**Changes required:**

1. Update `.input-field` class: `text-xs` → `text-base` (16px)
2. If visually smaller size needed, use `transform: scale(0.875)` with `transform-origin: left`
3. Verify all custom inputs across codebase use 16px minimum

**Source:** `globals.css` lines 614-616

### Claymorphism Utilities (Unchanged)

- Maintain existing shadow, radius, and spacing utilities
- Mobile shadow reduction already implemented (globals.css lines 743-753)
- No new utilities needed for this phase
