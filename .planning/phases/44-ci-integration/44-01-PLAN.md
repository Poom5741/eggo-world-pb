Create GitHub Actions workflow file `.github/workflows/e2e-tests.yml` with the following structure per user decisions:

**Triggers (per D-01, D-02, D-04):**

- `on: pull_request: branches: [main]` with path filtering for `apps/web/**`, `tests/**`, `wallet-api/**`
- `workflow_dispatch` for manual debugging

**Job configuration:**

- Single job `e2e-tests` on `ubuntu-latest`
- Use `oven-sh/setup-bun@v2` with `bun-version: latest` (follow pr-checks.yml pattern)
- Install project dependencies with `bun install`

**Docker services setup (per D-11):**

- Run `docker compose -f docker-compose.e2e.yml up -d` to start all services
- Wait for health checks using a shell loop that polls service health endpoints:
  - wallet-api: `curl -sf http://localhost:3001/health`
  - anvil: `curl -sf -X POST http://localhost:8545 -d '{"jsonrpc":"2.0","method":"eth_blockNumber","params":[],"id":1}'`
  - frontend: `curl -sf http://localhost:3000`
- Use 60-second timeout for health check wait loop

**Playwright execution (per D-05, D-06):**

- Run `bun run test:e2e --workers=2 --retries=1` (CLI override for workers)
- The playwright.config.ts already has CI-specific retries (2), but add CLI retry for extra safety
- Set timeout environment: `PLAYWRIGHT_TIMEOUT=60000` (per Claude's discretion)
- Set `CI=true` environment variable (Playwright config checks this)

**Do NOT:**

- Create matrix strategy (per D-07: single job is simpler)
- Add nightly scheduled runs (per D-03: PR-only)
- Use different Bun version than existing workflows
