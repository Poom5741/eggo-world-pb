<action>
Implement two-phase VRF for breeding in EggNFT.sol:

1. Add new mapping for breeding pending hatches (after line 103):

```solidity
mapping(uint256 => uint256) private breedingRequestIdToTokenId; // breeding requestId → tokenId
mapping(uint256 => PendingHatch) private breedingHatches; // breeding requestId → hatch data
```

2. Add VRF events for breeding (after line 80):

```solidity
event BreedingVRFRequested(uint256 indexed tokenId, uint256 indexed requestId);
event BreedingClaimed(uint256 indexed tokenId, uint256 animalTokenId);
```

3. Modify breedAnimals (line 394) — remove the pseudorandom rarity calculation. Instead:

- Keep the egg minting but DON'T determine rarity yet
- Store `rarity_seed: 0` initially (or use a sentinel value)
- Mark breeding egg as "pending VRF" state by setting is_hatched = false (already is)
- The rarity is only determined when hatchBreedingEgg is called with VRF

4. Add `requestBreedingVRF(uint256 tokenId)` function (similar to hatchEgg):

```solidity
function requestBreedingVRF(uint256 tokenId) external nonReentrant returns (uint256 requestId) {
    require(ownerOf(tokenId) == msg.sender, "Not token owner");
    EggProperties storage props = _eggProperties[tokenId];
    require(props.is_breeding_egg, "Not a breeding egg");
    require(!props.is_hatched, "Egg already hatched");

    requestId = s_vrfCoordinator.requestRandomWords(...);
    breedingRequestIdToTokenId[requestId] = tokenId;
    // Store hatch data
    emit BreedingVRFRequested(tokenId, requestId);
    return requestId;
}
```

5. Modify `fulfillRandomWords` to handle both hatch and breeding VRF requests

6. Modify `hatchBreedingEgg` to use VRF-fetched randomness (line 316): add VRF check requirement

7. Add `claimBreeding(uint256 tokenId)` function that calls hatchBreedingEgg after VRF is fulfilled
   </action>
