## Design System

| Property          | Value                                                                                                |
| ----------------- | ---------------------------------------------------------------------------------------------------- |
| Tool              | none (manual claymorphism system)                                                                    |
| Preset            | not applicable                                                                                       |
| Component library | Radix UI primitives (Dialog, Progress, Toast) via custom shadcn-style components                     |

| Font              | Geist (body/UI), Press Start 2P (headings, NFT labels) — mapped via `--font-sans` and `--font-pixel` |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage                                                              |
| ----- | ----- | ------------------------------------------------------------------ |
| xs    | 4px   | Checkbox-to-label gap, icon gaps, inline padding                   |
| sm    | 8px   | Compact element spacing, card internal gaps                        |
| md    | 16px  | Default element spacing, dialog content padding, grid gap (mobile) |
| lg    | 24px  | Section padding, grid gap (desktop), clay card padding             |
| xl    | 32px  | Dialog content vertical spacing, layout gaps                       |
| 2xl   | 48px  | Major section breaks (dialog header to content)                    |
| 3xl   | 64px  | Page-level spacing (not used within dialog)                        |

**Exceptions:**

- Touch targets minimum 44×44px (WCAG 2.2, per QUAL-04) — checkbox tap area must be ≥ 44px
- Food card grid gap: 12px on mobile (`gap-3`), 16px on desktop (`md:gap-4`) — uses `gap-clay-sm` / `gap-clay` from existing design system
- Claymorphism padding: 12px (`p-clay-sm`), 16px (`p-clay`), 24px (`p-clay-lg`) per DESIGN_SYSTEM.md

**Source:** `.planning/DESIGN_SYSTEM.md` §Spacing & Layout, `globals.css` §Claymorphism Spacing Utilities

## Interaction Patterns

### Mode Selection

1. Dialog opens → defaults to "Quick Fill" mode (preserves existing behavior)
2. User taps "Pick Manually" tab → grid of food NFTs appears, selection counter resets to "0/10"
3. User taps "Quick Fill" tab → manual selections cleared, returns to quick-fill confirmation

### Manual Food Selection

1. Tap food card → checkbox toggles, card enters selected state (border + background change)
2. Counter updates immediately: "1/10 food selected"
3. Max 10 selections → 11th tap ignored (no error, card doesn't toggle)
4. Tap selected card → deselects, counter decrements
5. Submit button disabled when 0 selected, enabled when 1-10 selected

### Quick-Fill Flow (Existing, Preserved)

1. Tap "FEED ME" → system fetches 10 food items from PocketBase
2. If < 10 items available → show insufficient food empty state
3. If 10+ items → set `confirmed = true`, show confirmation dialog
4. Confirmation dialog shows: "Confirm Feed?" with egg ID and food count
5. Tap "Confirm" → submit blockchain transaction
6. Tap "Cancel" → return to step 1

### Blockchain Transaction

1. Submit button → `loading = true`, all buttons disabled
2. Show spinner + "Submitting..." text on button
3. On success: toast "Egg Fed!", dialog closes, egg card polls for update
4. On failure: toast "Feed Failed", food items restored to picker state (D-14, D-17)

### Error Recovery

1. Blockchain transaction fails → error toast appears
2. All 10 food items restored to picker (optimistic rollback)
3. User can retry with same or different selection
4. PocketBase `food_nfts.consumed` flag NOT set until blockchain confirms (D-15)

### Dialog Dismissal

1. Tap X button or overlay → dialog closes, all state resets
2. Press Escape key → same as X button
3. Tap Cancel button (manual mode) → dialog closes, state resets
4. On close: `selectedFoodIds = []`, `confirmed = false`, mode resets to "Quick Fill"

## State Specifications

### Loading States

| State                   | Trigger                                         | Visual                                                                                 |
| ----------------------- | ----------------------------------------------- | -------------------------------------------------------------------------------------- |
| Fetching food inventory | Dialog opens (manual mode) or Quick Fill tapped | Skeleton grid (8 cards) with pulse animation                                           |
| Submitting transaction  | User taps "Feed Egg" or "Confirm"               | Button shows spinner + "Submitting...", all buttons disabled, overlay semi-transparent |
| Egg card polling        | After successful feed, egg card updates         | "Updating..." badge (existing, `animate-pulse`)                                        |

### Empty States

| Condition                    | Heading           | Body                                                        | CTA                                           |
| ---------------------------- | ----------------- | ----------------------------------------------------------- | --------------------------------------------- |
| 0 food NFTs                  | "No Food NFTs"    | "Buy some from the marketplace to start feeding your eggs." | "Go to Marketplace" (links to `/marketplace`) |
| < 10 food NFTs (manual mode) | "Not Enough Food" | "You have {count} food NFTs. Need {needed} more to feed."   | None — show available cards, submit disabled  |
| < 10 food NFTs (quick-fill)  | N/A               | Inline error: "Not enough food: have {count}/10 pieces"     | None — return to dialog                       |

### Error States

| Error                 | Trigger                       | Toast Title           | Toast Body                                                            | Recovery                                          |
| --------------------- | ----------------------------- | --------------------- | --------------------------------------------------------------------- | ------------------------------------------------- |
| Blockchain tx failed  | `feedEgg()` returns false     | "Feed Failed"         | "Transaction failed. Your food items have been restored. Try again."  | User can retry; food items restored to picker     |
| Network error (fetch) | PocketBase fetch fails        | "Failed to Load Food" | "Could not load your food inventory. Check connection and try again." | Retry button in dialog                            |
| Egg already hatched   | `food_count >= 10` validation | "Egg Already Hatched" | "This egg has already hatched or is ready to hatch."                  | Dialog closes, user sees Hatch button on egg card |
| Not egg owner         | Ownership check fails         | "Access Denied"       | "You don't own this egg."                                             | Dialog closes                                     |

### Success States

| State           | Trigger                                        | Visual                                                                                                          |
| --------------- | ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Feed successful | Blockchain tx confirmed, 12+ blocks            | Toast: "Egg Fed!" + "Egg #{egg_id} has been fed successfully." Dialog closes. Egg card polling triggers update. |
| 10/10 reached   | After polling update shows `food_count === 10` | Egg card shows HATCH button (existing behavior), progress bar full, visual indicator (🎉 emoji or glow)         |

### Partial States

| State                    | Description                              | Visual                                                                      |
| ------------------------ | ---------------------------------------- | --------------------------------------------------------------------------- |
| 1-9/10 selected (manual) | User hasn't selected max                 | Counter shows "{n}/10", submit enabled but button text: "Feed Egg ({n}/10)" |
| 1-9/10 fed (polling)     | Egg partially fed from previous sessions | Progress bar shows partial fill, egg card displays "{n}/10 food items"      |

## Mobile Specifications

### Responsive Breakpoints

| Breakpoint              | Behavior                                                                                                                    |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| < 640px (mobile)        | Food grid: 2 columns. Dialog: `max-w-md`, full-width minus 2rem padding. Mode toggle: stacked vertically if text overflows. |
| 640px - 767px           | Food grid: 2 columns. Dialog: `max-w-md`.                                                                                   |
| 768px - 1023px (tablet) | Food grid: 3 columns. Dialog: `max-w-lg`.                                                                                   |
| ≥ 1024px (desktop)      | Food grid: 4 columns. Dialog: `max-w-lg`.                                                                                   |

### Touch Targets

- All interactive elements (cards, buttons, checkboxes, tabs): minimum 44×44px
- Food card tap area: entire card (140px height × grid column width)
- Checkbox tap area: 44×44px (24px visual + 10px padding on all sides)
- Mode toggle tabs: 44px height minimum
- Submit/Cancel buttons: existing clay-md/clay-lg sizes already meet 44px minimum

### Scroll Behavior

- Food picker grid: max-height 400px, scrollable (`overflow-y-auto`)
- Scroll snap: none (free scroll)
- Scrollbar styling: thin (`scrollbar-thin`), track `--surface-container`, thumb `--primary`
- iOS: `-webkit-overflow-scrolling: touch`

### Safe Area

- Dialog respects `env(safe-area-inset-bottom)` for iPhone notch
- Bottom button row: padding-bottom `max(16px, env(safe-area-inset-bottom))`

### Performance

- Mobile shadow reduction: `shadow-clay-xl` → `shadow-clay-md` (per `globals.css` lines 760-769)
- Food card hover effect disabled on mobile (touch devices)
- `will-change: box-shadow` on clay elements (GPU acceleration, per `globals.css` lines 746-757)
- Skeleton loading: 8 cards max (matches grid capacity at desktop 4-col × 2 rows)
