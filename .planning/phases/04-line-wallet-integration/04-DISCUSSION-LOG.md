## Wallet Technology Choice

| Option                   | Description                                                           | Selected |
| ------------------------ | --------------------------------------------------------------------- | -------- |
| Keep ethers v6           | Current implementation, EVM-compatible, standard library              |          |
| Switch to dacc-js v0.0.5 | Reference implementation, DACC-specific format, decentralized storage | ✓        |

**User's choice:** Switch to dacc-js v0.0.5  
**Notes:** User requested integration from pkbase-wallet reference. DACC provides decentralized storage features that ethers doesn't have. Wallet format will change from EVM-compatible to DACC-specific.

## Password Management

| Option                          | Description                                          | Selected |
| ------------------------------- | ---------------------------------------------------- | -------- |
| Auto-generated (20-char random) | Generated by hook, no user interaction needed        | ✓        |
| User-provided (12-120 chars)    | User enters password during signup, validated by API |          |

**User's choice:** Keep auto-generated passwords  
**Notes:** Better UX — users don't need to remember or manage passwords. Generated in PocketBase hook before calling wallet API.

## API Structure

| Option                  | Description                                 | Selected |
| ----------------------- | ------------------------------------------- | -------- |
| Keep current JavaScript | Simple, no migration needed                 |          |
| Migrate to TypeScript   | Type safety, match reference implementation | ✓        |

**User's choice:** Migrate to TypeScript + Express + Bun runtime  
**Notes:** Align with reference implementation structure. Keep endpoint as `/api/wallet/create` (not `/api/v1/wallet/create`) for backward compatibility.

## User Fields

## Backward Compatibility

| Option                        | Description                              | Selected |
| ----------------------------- | ---------------------------------------- | -------- |
| Force migration for all users | Break existing users, start fresh        |          |
| Support both wallet types     | New users get DACC, existing keep ethers | ✓        |

**User's choice:** Support both wallet types during migration  
**Notes:** New users get DACC wallets via dacc-js. Existing users keep ethers wallets. Add migration path for later (Phase 4D).

## Migration Approach

| Option             | Description                             | Selected |
| ------------------ | --------------------------------------- | -------- |
| Big bang migration | Everything at once                      |          |

**User's choice:** Phased migration  
**Notes:**

- Phase 4A: TypeScript migration (no logic changes)

- Phase 4D: Deprecate ethers wallets (future phase)
