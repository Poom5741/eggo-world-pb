## Objective

Build the Pool Balance & Treasury Withdrawal section of the admin treasury page. Admin can view USDT pool balances (Treasury + CoinStor + Total) with manual refresh and auto-refresh after withdrawals, then withdraw treasury funds via MetaMask with comprehensive error handling. Implementation leverages Phase 64's pool balance endpoint, Phase 66's viem transaction patterns, and follows established shadcn/ui conventions.

**Must-haves (goal-backward derived):**

1. Pool balance card displaying Total, Treasury, and CoinStor balances with proper formatting
2. Manual refresh + auto-refresh after successful withdrawals
3. Withdrawal form with real-time validation, gas estimation, and ownership-based enablement
4. Comprehensive error handling for transaction reverts, RPC failures, and contract read errors
5. Step-by-step transaction progress indication
6. Integration with Phase 66 ownership status for withdrawal enablement

## Locked Decisions from CONTEXT.md

### Balance Display Design

- **D-17:** Single summary card showing all three pool balances (Treasury 46%/6%, CoinStor 4%, Total). Total balance emphasized at top with larger font, Treasury and CoinStor shown below as supporting details.
- **D-18:** Full currency format with dollar signs, thousands separators, and USDT labels (e.g., "$1,234.56 USDT"). 2 decimal places for all amounts.
- **D-19:** Standard loading/error patterns — skeleton placeholders during initial fetch and manual refresh, inline Alert component for errors with retry button.

### Withdrawal Form UX

- **D-20:** Direct MetaMask transaction flow — user clicks Withdraw, MetaMask pops up immediately, transaction signs and sends without intermediate confirmation step.
- **D-21:** Gas estimation displayed before withdrawal in USDT/BNB to help admin understand transaction cost.
- **D-22:** Detailed progress indication during transaction — step-by-step feedback: "Signing..." → "Sending..." → "Confirming..." → "Done".
- **D-23:** Success/failure handling via Alerts — success shows green alert + auto-refreshes pool balances; failure shows red error alert + retry button.
- **D-24:** Real-time validation as user types — immediate feedback if withdrawal amount ≤ 0 or exceeds available treasury balance.
- **D-25:** Large withdrawal safeguards — warning message for amounts >10% of treasury or >$1000 USDT, but withdrawal still allowed.

### Ownership Integration

- **D-26:** Strict ownership check — withdrawal button disabled until user accepts CommissionDistribution ownership (from Phase 66). Shows tooltip: "Accept CommissionDistribution ownership first" + link to Phase 66 ownership section.
- **D-27:** Visual connection to Phase 66 — helpful guidance messaging links to ownership section rather than displaying redundant status badges.

### Refresh & Data Updates

- **D-28:** Auto-refresh balances after successful withdrawal transaction completes + always-visible manual refresh button in balance card header.
- **D-29:** Skeleton placeholders during manual refresh (same as initial load) — clear visual indication that data is updating.
- **D-30:** Error handling for refresh failures — show error alert but keep previous balance data visible, refresh button remains enabled for retry.

### Wave 2: Withdrawal Form (Depends on Wave 1)

#### Task 2.1: Treasury Withdrawal Logic

**File:** `apps/web/hooks/use-treasury-withdrawal.ts`
**Dependencies:** Phase 66 `useContractOwnership`, Phase 65 `useMetaMask`, Wave 1
**Confidence:** HIGH [VERIFIED: viem documentation, Phase 66 patterns]

**Actions:**

1. Create `useTreasuryWithdrawal()` hook with withdrawal transaction logic
2. Integrate `useMetaMask()` for wallet client and `useContractOwnership('CommissionDistribution')` for ownership check
3. Implement `handleWithdraw(amount: bigint)` function:
   - **Step 1 (D-22):** `setStep('validating')` — validate ownership via `isOwner` from useContractOwnership
   - **Step 2 (D-21):** Use `simulateContract` to estimate gas: `const { request } = await publicClient.simulateContract({ ...withdrawTreasury args })`
   - **Step 3 (D-21):** Calculate gas cost in USDT: `gasEstimate * gasPrice` → display to user
   - **Step 4 (D-20, D-22):** `setStep('signing')` — call `writeContract(walletClient, request)` to trigger MetaMask
   - **Step 5 (D-22):** `setStep('confirming')` — await `publicClient.waitForTransactionReceipt({ hash })`
   - **Step 6 (D-23):** On `receipt.status === 'success'`: `setStep('done')`, call `autoRefreshAfterWithdrawal()` from Wave 1, show success alert
4. Implement comprehensive error handling per ERR-01, ERR-02:
   - Parse viem `BaseError` and `ContractFunctionRevertedError` for revert reasons
   - Extract error name from `revertError.data?.errorName`
   - Map to user-friendly messages: `"Amount must be > 0"`, `"Insufficient treasury balance"`, `"Only owner can withdraw"`
   - For RPC/network errors: show retry option with context
5. Return state: `{ withdrawalStep, gasEstimation, handleWithdraw, error }`

**Verification:**

- Ownership check prevents withdrawal if not owner (WDRW-04)
- Gas estimation displayed before MetaMask prompt (D-21)
- Transaction progress steps shown: validating → signing → confirming → done (D-22)
- Successful withdrawal triggers pool balance auto-refresh (D-28, D-23)
- Failed withdrawal shows specific revert reason (ERR-01)
- RPC failures show retry option (ERR-02)

10. Display transaction progress per D-22:

## Risk Mitigation

### High-Risk Areas

1. **Phase 64 endpoint availability**
   - **Risk:** Endpoint down or returns incorrect data
   - **Mitigation:** Task 1.1 implements graceful error handling with retry button; previous balance data kept visible on error

2. **Viem transaction complexity**
   - **Risk:** Gas estimation or error parsing more complex than researched
   - **Mitigation:** Task 3.3 dedicated to error handling polish; fallback to generic error messages if parsing fails

3. **Ownership verification race conditions**
   - **Risk:** Ownership status changes between check and transaction
   - **Mitigation:** Re-verify ownership in `use-treasury-withdrawal.ts` before every withdrawal

### Rollback Strategy

If Phase 67 fails:

1. **Disable withdrawal section** — Comment out `<WithdrawalForm />` in TreasuryWithdrawalSection
2. **Keep balance display** — PoolBalanceCard is read-only, safe to leave enabled
3. **Fallback to manual withdrawals** — Admin can call `withdrawTreasury` directly via Etherscan
