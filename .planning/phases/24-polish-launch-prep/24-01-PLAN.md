# Phase 24 Plan 01: Error Boundaries & Monitoring Dashboard

**Wave:** 1 — Infrastructure  
**Status:** Ready to execute

## Objective

Add production-grade error boundaries to all authenticated routes and create admin monitoring dashboard for transaction success rates.

## Scope

### Error Boundaries

- Add `error.tsx` to 6 authenticated routes: `/dashboard`, `/mint`, `/referrals`, `/commissions`, `/tiers`, `/breeding`
- Extend existing `marketplace/error.tsx` pattern with retry + fallback UI

### Monitoring Dashboard

- Create `transaction_logs` collection in PocketBase
- Create `/admin/monitoring` page showing transaction metrics
- Add logging to existing hooks to populate transaction_logs collection

## Implementation Decisions (from CONTEXT.md)

- D-01: Route-level error boundaries for all authenticated routes
- D-02: Error reporting via console + Cloudflare Analytics
- D-03: Graceful degradation: retry button + fallback UI
- D-04: Admin page in app at `/admin/monitoring`
- D-05: Metrics scope: transaction success rates (mint, buy, feed, hatch, breed)
- D-06: Data source: PocketBase `transaction_logs` collection

### Task 1.2: Create Transaction Logs Collection

**Objective:** Create `transaction_logs` collection in PocketBase to store transaction outcomes for monitoring

**Steps:**

1. Read existing collection schema: `apps/backend/collections/marketplace_items.json` — reference for field structure
2. Create `apps/backend/collections/transaction_logs.json` with fields:
   - `id` (auto-generated)
   - `user` (relation to users collection)
   - `tx_hash` (text, indexed)
   - `tx_type` (text, enum: "mint", "buy", "feed", "hatch", "breed")
   - `status` (text, enum: "success", "failed", "pending")
   - `error_message` (text, nullable)
   - `gas_used` (number, nullable)
   - `timestamp` (datetime, auto-set to created)
3. Set API rules:
   - List rule: `@request.auth.id != ""` (authenticated users can view)
   - Create rule: empty (only backend hooks create)
   - Update rule: empty (immutable after creation)
4. Import collection via PocketBase admin or migration script

### Task 1.3: Add Transaction Logging to Hooks

**Objective:** Modify existing hooks to log transaction outcomes to `transaction_logs` collection

**Steps:**

1. Identify hooks to modify:
   - `apps/backend/pb_hooks/18-breed-animals.pb.js` — breed transactions
   - `apps/backend/pb_hooks/19-mint-egg.pb.js` (or similar) — mint transactions
   - `apps/backend/pb_hooks/16-feed-egg.pb.js` — feed transactions
2. Read each hook to understand transaction flow
3. After successful transaction, add logging:
   ```javascript
   try {
     $app.collection("transaction_logs").create({
       user: user.id,
       tx_hash: txHash,
       tx_type: "breed", // or 'mint', 'feed', etc.
       status: "success",
       gas_used: gasEstimate,
     })
   } catch (logErr) {
     console.error("Failed to log transaction:", logErr)
   }
   ```
4. After failed transaction, add error logging:
   ```javascript
   try {
     $app.collection("transaction_logs").create({
       user: user.id,
       tx_hash: txHash || null,
       tx_type: "breed",
       status: "failed",
       error_message: error.message,
     })
   } catch (logErr) {
     console.error("Failed to log error transaction:", logErr)
   }
   ```
5. Test hooks locally to verify logging works

**Acceptance Criteria:**

- [x] All 3 hooks modified to log successful transactions
- [x] All 3 hooks modified to log failed transactions
- [x] Logging wrapped in try-catch (non-blocking)
- [x] Hooks still function correctly after modification
- [x] Transaction logs appear in `transaction_logs` collection

**Files to Modify:**

- `apps/backend/pb_hooks/18-breed-animals.pb.js`
- `apps/backend/pb_hooks/16-feed-egg.pb.js`
- `apps/backend/pb_hooks/19-mint-egg.pb.js` (verify filename)

**Dependencies:** Task 1.2 (collection must exist)

### Task 1.4: Create Admin Monitoring Dashboard

**Objective:** Create `/admin/monitoring` page displaying transaction success rates from PocketBase

**Steps:**

1. Create route structure:
   - `apps/web/app/admin/monitoring/page.tsx`
2. Fetch transaction logs:
   ```typescript
   const logs = await pb.collection("transaction_logs").getList(1, 1000, {
     sort: "-created",
   })
   ```
3. Calculate metrics:
   - Total transactions by type
   - Success rate by type (success / total × 100)
   - Recent failures (last 10 failed transactions)
   - Average gas used
4. Display metrics in claymorphism cards:
   ```tsx
   <div className="grid gap-6 md:grid-cols-2 lg:grid-cols-4">
     <StatCard label="Mint Success Rate" value={`${mintRate}%`} />
     <StatCard label="Feed Success Rate" value={`${feedRate}%`} />
     <StatCard label="Breed Success Rate" value={`${breedRate}%`} />
     <StatCard label="Total Transactions" value={totalCount} />
   </div>
   ```
5. Add recent failures table:
   ```tsx
   <Table>
     <TableHeader>
       <TableRow>
         <TableHead>Timestamp</TableHead>
         <TableHead>Type</TableHead>
         <TableHead>Error</TableHead>
       </TableRow>
     </TableHeader>
     <TableBody>
       {recentFailures.map((log) => (
         <TableRow key={log.id}>
           <TableCell>{formatDate(log.created)}</TableCell>
           <TableCell>{log.tx_type}</TableCell>
           <TableCell>{log.error_message}</TableCell>
         </TableRow>
       ))}
     </TableBody>
   </Table>
   ```
6. Style with claymorphism design system
7. Add access control (admin-only or authenticated users per D-04)

**Acceptance Criteria:**

- [x] `/admin/monitoring` page loads with metrics
- [x] Success rate calculated correctly per transaction type
- [x] Recent failures table displays error details
- [x] Claymorphism styling consistent with existing dashboard
- [x] Page accessible only to authenticated users
- [x] No TypeScript errors, no lint warnings

**Files to Create:**

- `apps/web/app/admin/monitoring/page.tsx`

**Dependencies:** Task 1.2, Task 1.3 (collection exists and populated)

**Risk:** Medium — requires data to exist for meaningful metrics
