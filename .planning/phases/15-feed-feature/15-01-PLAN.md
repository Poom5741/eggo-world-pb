**Food selection handler (toggle with 10-item max):**

```typescript
const handleSelectFood = (foodId: number) => {
  setSelectedFoodIds(
    (prev) =>
      prev.includes(foodId)
        ? prev.filter((id) => id !== foodId)
        : prev.length < 10
          ? [...prev, foodId]
          : prev // Prevent selecting more than 10
  )
}
```

## Trust Boundaries

| Boundary             | Description                                                       |
| -------------------- | ----------------------------------------------------------------- |
| Client → Backend API | Food selection IDs submitted via POST /api/v2/feed-egg            |
| Backend → Blockchain | Wallet API executes feedEgg transaction with user's decrypted key |
| Backend → Database   | Atomic update of egg.food_count + food.is_consumed                |

## STRIDE Threat Register

| Threat ID | Category    | Component                               | Disposition | Mitigation Plan                                                                                                                      |
| --------- | ----------- | --------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| T-15-01   | Tampering   | feed-dialog.tsx → feedEgg()             | mitigate    | Backend (16-feed-egg.pb.js) validates egg ownership and food ownership before blockchain call                                        |
| T-15-02   | Tampering   | feed-dialog.tsx → food selection        | mitigate    | Client validates selectedFoodIds.length <= 10 before submit; backend validates food ownership and is_consumed = false                |
| T-15-03   | Tampering   | feed-dialog.tsx → feedEgg(egg.token_id) | mitigate    | Backend validates egg_token_id matches authenticated user's egg; rejects if food_count >= 10 (already hatched)                       |
| T-15-04   | Repudiation | feed-egg endpoint                       | mitigate    | Backend uses blockchain tx hash as idempotency key; double-submit returns existing record                                            |
| T-15-05   | Spoofing    | egg-card.tsx → HATCH button             | accept      | HATCH button visible client-side based on food_count >= 10; backend validates ownership again on hatch (Phase 12 already implements) |
