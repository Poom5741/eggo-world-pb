## Cross-Phase Integration Issues

### Critical Issues

#### 1. SEC-06: Missing 12-Block Confirmation Wait (CRITICAL)

**Affected Requirements:** SEC-06  
**Severity:** Critical (Security)  
**Location:** `apps/backend/pb_hooks/13-track-deposit.pb.js`

**Issue:** The deposit tracking hook marks deposits as "confirmed" immediately upon detection (line 123), without waiting for 12 block confirmations as explicitly required by SEC-06. This creates a security vulnerability where chain reorgs could invalidate deposits that were already credited to users.

**Current Behavior:**

```javascript
// Line 123: Marks confirmed immediately
deposit.confirmed = true
```

**Required Behavior:**

```javascript
// Should wait 12 blocks before marking confirmed
// Track pending deposits separately
// Verify parent hash continuity to detect reorgs
```

**Impact:** Users could receive credited USDT from deposits that later get reorged out of the chain, leading to potential double-spending or financial loss.

**Fix Required:**

1. Add `pending` state to deposits collection
2. Implement 12-block confirmation check in polling loop
3. Add chain reorg detection via parent hash verification
4. Update frontend to show pending → confirmed transition

---

#### 2. FEAT-01: FeaturedEggHero "FEED ME" Button is Dead Code (HIGH)

**Affected Requirements:** FEAT-01  
**Severity:** High (User-Facing Bug)  
**Location:** `apps/web/app/eggs/page.tsx` line 88-91

**Issue:** The most prominent feed button on the eggs page (FeaturedEggHero component) is wired to a TODO stub that only logs to console:

```typescript
// Line 88-91
const handleFeedEgg = (eggId: string) => {
  console.log("Feed egg:", eggId)
  // TODO: Open FeedDialog
}
```

**Current Behavior:** User clicks "FEED ME" button → nothing happens (only console.log)

**Expected Behavior:** User clicks "FEED ME" button → FeedDialog opens → user selects food → feeds egg

**Impact:** Users cannot feed their featured egg from the hero section. They must scroll down to the egg grid and use the "Manage Egg" button instead. This is confusing and breaks the primary user flow.

**Fix Required:**

```typescript
const handleFeedEgg = (eggId: string) => {
  const egg = eggs.find((e) => e.egg_id === eggId)
  if (egg) {
    setFeedingEgg(egg)
    setFeedDialogOpen(true)
  }
}
```

### Medium Severity Issues

#### 3. Mobile Breakpoint Inconsistency

**Affected Requirements:** QUAL-03, QUAL-05  
**Severity:** Medium  
**Location:** `apps/web/hooks/use-mobile.ts` vs `apps/web/components/ui/use-mobile.tsx`

**Issue:** Phase 14 updated the mobile breakpoint to 1024px in `ui/use-mobile.tsx`, but `hooks/use-mobile.ts` still uses 768px. Components importing from `hooks/use-mobile.ts` (e.g., `sidebar.tsx`) get the wrong breakpoint.

**Impact:** Sidebar may show/hide at wrong screen sizes, causing layout issues on tablets (768px-1024px range).

**Fix Required:** Update `hooks/use-mobile.ts` to use `MOBILE_BREAKPOINT = 1024` to match `ui/use-mobile.tsx`.

#### 4. Phase 13 Documentation Inconsistency

**Affected Requirements:** SEC-05, SEC-06, SEC-07, SEC-08  
**Severity:** Medium (Documentation)
